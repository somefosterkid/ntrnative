# The lockstep tester's game variables (docs/lockstep.md): what both sides dump each frame, by name.
#
# NAME  TYPE  DS-PATH  PORT-EXPR  [if NAME==VALUE]
#
# Columns are separated by two or more spaces (NAME, TYPE and DS-PATH have none; PORT-EXPR may have single ones);
# the optional last column starts with "if ".
#
# TYPE   u8 u16 u32 s8 s16 s32 u64 (a JSON number; u64 as a "0x..." string)
#        ptr       the pointer's null-ness: 0 or 1 (the values differ between the DS and a PC)
#        fn        a code or data pointer, by symbol name (DS: config/b_us/arm9/**/symbols.txt; an overlay address
#                  that several overlays' symbols share gives "a|b|c"; unknown: "?0xADDR". Port: the ELF's symbol)
#        hash:N    crc32 of N bytes at the address, as 8 hex digits (pointer-free data only)
#        rel:PATH  this u32 minus the u32 at PATH (both DS pointers; port: the same difference of its pointers)
# DS-PATH  BASE then steps, no spaces: BASE is a symbol of symbols.txt (main, itcm, dtcm) or 0xADDR; `.OFF` adds OFF
#        (hex), `->OFF` reads the u32 at the current address (a pointer: 0 makes the var null) and adds OFF. The var is
#        read from the final address. Offsets are the DS layout's: tools/lockstep/ds_offsets.py computes them with
#        mwccarm ('OFF(Field, player)'; --tu src/system/game_data.c for GameData).
# PORT-EXPR  a C expression in the PC build (gdb evaluates the same): its value, or the address hashed. A static
#        (data_020aa1a0, data_020aa1a4, data_021469f8) is a local symbol of the PC exe: nm shows it; port code reads
#        it through the ELF symbol table or gdb, not by name in C.
# if     read only when the other var (read first, above) has that value; else null. Null also when a pointer on the
#        path is null.
#
# Not here (the dumper's own fields, docs/lockstep.md): the record's frame, the V-blank count, the keys, the screens.
